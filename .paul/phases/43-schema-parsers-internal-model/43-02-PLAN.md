## AC-1: Excel data dictionary parser produces FileSchemaDefinition
```gherkin
Given an Excel .xlsx file with columns: field_name, data_type, length, start_position, decimal_places, nullable, pii_type, fk_reference, comp_type
When parsed by ExcelDictionaryParser.parse()
Then it returns a FileSchemaDefinition with correct field definitions
And missing optional columns (start_position, decimal_places, pii_type, fk_reference, comp_type) are handled with defaults
And header row is detected via fuzzy matching (case-insensitive, underscore/space tolerant)
And validation errors are raised for missing required columns (field_name, data_type, length)
And empty rows are skipped
```

## AC-2: File schema API endpoints accept all four schema sources
```gherkin
Given the synthetic API router
When POST /projects/{project_id}/synthetic/file-schemas/upload-copybook is called with multipart file
Then it parses the copybook and returns the FileSchemaDefinition as JSON
And saves it to the database

When POST /projects/{project_id}/synthetic/file-schemas/upload-dictionary is called with .xlsx file
Then it parses the Excel dictionary and returns the FileSchemaDefinition as JSON
And saves it to the database

When POST /projects/{project_id}/synthetic/file-schemas/manual is called with JSON body
Then it creates a FileSchemaDefinition from the field definitions and saves it

When POST /projects/{project_id}/synthetic/file-schemas/from-discovery is called with table name
Then it pulls column metadata from existing discovery results and creates a FileSchemaDefinition

When GET /projects/{project_id}/synthetic/file-schemas is called
Then it returns all saved file schemas for the project
```

## AC-3: File schemas are persisted with full metadata
```gherkin
Given a FileSchemaDefinition created from any source
When saved via the repository
Then all fields, format, encoding, record length, metadata, and output filename are stored
And schemas can be retrieved by ID or listed by project_id
And the persistence model uses JSONB for the fields array
```

<task type="auto">
  <name>Task 1: Implement Excel data dictionary parser</name>
  <files>backend/app/infrastructure/parsers/excel_dictionary_parser.py</files>
  <action>
    Create ExcelDictionaryParser class:

    Method: parse(file_bytes: bytes, name: str = "dictionary", target_format: FileFormat = FileFormat.CSV, target_encoding: EncodingType = EncodingType.UTF8) -> FileSchemaDefinition

    Logic:
    1. Load workbook from bytes using openpyxl (read_only=True for efficiency)
    2. Read first sheet
    3. Find header row: scan first 5 rows for a row containing "field_name" or "field name" or "name" (case-insensitive, strip whitespace)
    4. Map columns via fuzzy matching:
       - Required: field_name (aliases: "name", "field", "column_name", "column")
       - Required: data_type (aliases: "type", "datatype", "data type")
       - Required: length (aliases: "len", "size", "field_length")
       - Optional: start_position (aliases: "start", "position", "offset") — default: auto-compute
       - Optional: decimal_places (aliases: "decimals", "scale") — default: 0
       - Optional: nullable (aliases: "null", "is_nullable") — default: True
       - Optional: pii_type (aliases: "pii", "sensitive_type") — default: None
       - Optional: fk_reference (aliases: "fk", "foreign_key") — default: None, parse as "file.field" string
       - Optional: comp_type (aliases: "comp", "usage", "computational") — default: NONE
    5. Validate: raise ValueError if required columns not found
    6. Iterate data rows:
       - Skip empty rows (no field_name)
       - Create FileFieldDefinition for each row
       - Map data_type strings to canonical types: "char"/"varchar"/"string"/"alpha" → "alphanumeric", "num"/"number"/"int"/"integer" → "numeric", "dec"/"decimal"/"float" → "decimal", "pack"/"packed" → "packed_decimal", "bin"/"binary" → "binary"
       - Parse comp_type: "comp"/"comp-0"/"binary" → COMP, "comp-3"/"packed" → COMP_3, else NONE
       - Compute byte_length from data_type + length + comp_type (same logic as copybook parser)
       - Auto-compute start_position if not provided (sequential from 0)
       - Parse fk_reference "customers.id" → {"file": "customers", "field": "id"}
    7. Build and return FileSchemaDefinition

    Method: parse_file(file_path: Path, **kwargs) -> FileSchemaDefinition
    - Read file as bytes, delegate to parse()

    Requires: openpyxl (add to pyproject.toml if not present)
  </action>

<task type="auto">
  <name>Task 2: Add persistence layer and API endpoints for file schemas</name>
  <files>backend/app/domain/synthetic/file_schema_repository.py, backend/app/infrastructure/persistence/models/file_schema.py, backend/app/infrastructure/persistence/sqlalchemy/file_schema_repo.py, backend/app/api/v1/synthetic.py</files>
  <action>
    1. Create domain repository ABC (file_schema_repository.py):
       - FileSchemaRepository ABC extending Repository[FileSchemaDefinition] pattern
       - Methods: save(schema: dict) -> dict, get(schema_id: UUID) -> dict | None, list_by_project(project_id: UUID) -> list[dict], delete(schema_id: UUID) -> None
       - Note: uses dict since FileSchemaDefinition is a value object, not an entity. Storage wraps it with id/project_id/timestamps.

    2. Create SQLAlchemy model (persistence/models/file_schema.py):
       - Table: file_schemas
       - Columns: id (UUID PK), project_id (UUID FK), name (String), file_format (String), encoding (String), record_length (Integer), has_rdw (Boolean), output_filename (String nullable), fields (JSONB — serialized list of FileFieldDefinition dicts), metadata_ (JSONB), created_at, updated_at
       - Follow pattern from persistence/models/synthetic.py

    3. Create SQLAlchemy repository (sqlalchemy/file_schema_repo.py):
       - SQLAlchemyFileSchemaRepository implementing the ABC
       - save(): serialize FileSchemaDefinition fields to JSONB, store
       - get(): load + deserialize
       - list_by_project(): filter by project_id
       - Follow pattern from sqlalchemy/synthetic_repo.py

    4. Add 5 endpoints to synthetic.py (append after existing endpoints):

       a. POST /file-schemas/upload-copybook
          - Accept: multipart file upload (UploadFile)
          - Parse with CopybookParser
          - Save via repository
          - Return JSON representation

       b. POST /file-schemas/upload-dictionary
          - Accept: multipart .xlsx upload (UploadFile)
          - Optional query params: target_format, target_encoding
          - Parse with ExcelDictionaryParser
          - Save via repository
          - Return JSON representation

       c. POST /file-schemas/manual
          - Accept JSON body: {name, file_format, encoding, fields: [{name, data_type, length, ...}]}
          - Build FileSchemaDefinition from body
          - Run validate(), return errors if any
          - Save via repository
          - Return JSON representation

       d. POST /file-schemas/from-discovery
          - Accept JSON body: {table_name, connection_id, target_format?, target_encoding?}
          - Load discovery metadata for the table from existing discovery infrastructure
          - Map discovered columns → FileFieldDefinition (map SQL types to file types, preserve PII annotations)
          - Build FileSchemaDefinition
          - Save via repository
          - Return JSON representation

       e. GET /file-schemas
          - List all file schemas for the project
          - Return array of schema summaries (id, name, format, field_count, record_length, created_at)

    Pydantic request/response models:
    - FileSchemaResponse: id, name, file_format, encoding, record_length, field_count, output_filename, created_at
    - FileFieldResponse: name, data_type, length, byte_length, start_position, decimal_places, comp_type, nullable, pii_type
    - FileSchemaDetailResponse: extends FileSchemaResponse with fields: list[FileFieldResponse]
    - ManualSchemaRequest: name, file_format, encoding, fields list
    - DiscoverySchemaRequest: table_name, connection_id, target_format, target_encoding

    All endpoints require get_current_user dependency (auth).
    All endpoints use project_id path parameter.
    Log actions with structlog.
  </action>
