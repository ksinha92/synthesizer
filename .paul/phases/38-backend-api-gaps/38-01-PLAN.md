<objective>
Build 4 missing backend API endpoints that the frontend already calls but which have no handlers, plus 3 CRUD gaps in existing routers. All changes are backend-only — the frontend is already wired and waiting.

<acceptance_criteria>
## AC-1: RBAC Member Management (4 endpoints)
Given the admin router, when the frontend rbac-manager.tsx calls /admin/members endpoints, then:
- GET /admin/members returns paginated list of members with {id, email, full_name, role, added_at}
- POST /admin/members accepts {email, role} and creates a member (looks up or invites user by email)
- PUT /admin/members/{member_id} accepts {role} and updates the member's role
- DELETE /admin/members/{member_id} removes the member record
All endpoints require admin role. All mutations write to audit_logs.
Uses the existing project_members table (migration 010_rbac_audit).

## AC-2: Subset Config Listing
Given the subsetting router, when GET /projects/{project_id}/subset/configs is called, then return a list of all subset configs for the project with {id, name, source_connection_id, target_connection_id, target_percentage, target_row_count, root_tables, traversal_strategy, created_at}.

## AC-3: Masking Rule Update + Delete
Given the masking router:
- PUT /projects/{project_id}/masking/policies/{policy_id}/rules/{rule_id} accepts updated rule fields and returns the modified rule
- DELETE /projects/{project_id}/masking/policies/{policy_id}/rules/{rule_id} removes the rule and returns 204
Both verify the rule belongs to the specified policy. Both write audit logs.

## AC-4: Workflow Execution History
Given the workflow router, when GET /projects/{project_id}/workflows/{workflow_id}/executions is called, then return a paginated list of jobs where job_type="workflow" and reference_id=workflow_id, ordered by created_at desc. Each entry includes {id, status, progress, started_at, completed_at, error_message, created_at}.
</acceptance_criteria>
