## Goal
Backend endpoint to launch file-set generation + frontend store + file-output panel + page wiring.

## Output
- Backend `POST /projects/{id}/synthetic/file-sets/generate` accepting an inline FileSetDefinition + row_counts, dispatching `run_file_set_generation_task`.
- Frontend `useFileOutputStore` Zustand store for schemas, file set, jobs.
- `<FileOutputPanel>` component: schema picker (multi-select from project's file_schemas), per-schema format + row count, cross-file FK editor, Generate button, polling status + download link.
- Page change: add a "File output" tab alongside existing synthetic surface.
</objective>

<acceptance_criteria>

## AC-1: Generate endpoint dispatches Celery task
```gherkin
Given an authenticated user and a project
When they POST /projects/{id}/synthetic/file-sets/generate with a FileSetDefinition body
Then a JobModel row is created with job_type="file_set_generation"
And run_file_set_generation_task.delay(file_set_dict, project_id, job_id) is called
And the response is 202 with {"job_id": str}.
```

## AC-2: Store wraps the three flows
```gherkin
Given useFileOutputStore
When fetchSchemas(projectId) runs → loads /file-schemas
When generateFileSet({...}) runs → POSTs and stores the job_id
When pollJob(jobId) runs → GETs the job and updates status
When downloadBundle(jobId) → returns the download URL (callers can window.open)
```

## AC-3: UI flow is end-to-end usable
```gherkin
Given a project with one or more uploaded file schemas
When the user opens the "File output" tab
Then they see a list of schemas with checkboxes + per-row format dropdown + row count input
And clicking "Generate" launches a job
And the panel shows status (queued → running → completed/failed)
And on completed, a "Download zip" button reveals the bundle.
```

    ```python
    class FileSetGenerateRequest(BaseModel):
        file_set: dict  # FileSetDefinition.to_dict()
        row_counts: dict[str, int] | None = None


    @router.post("/file-sets/generate", status_code=202)
    async def generate_file_set(
        project_id: uuid.UUID,
        body: FileSetGenerateRequest,
        current_user: dict = Depends(get_current_user),
        session: AsyncSession = Depends(get_session),
    ):
        """Launch multi-file generation. Returns a job_id."""
        from app.infrastructure.persistence.models.job import JobModel
        from app.infrastructure.messaging.synthetic_tasks import run_file_set_generation_task

        # Build the file-set dict; include row_counts inside metadata so the task can pick them up later
        # (the orchestrator currently takes row_counts via __init__; we wrap that in the task body too)
        # For now, pass row_counts in the file_set dict as a top-level key the orchestrator can read.
        file_set_dict = body.file_set
        if body.row_counts:
            file_set_dict.setdefault("row_counts", body.row_counts)

        # Validate by attempting to deserialize
        from app.domain.synthetic.file_schema import FileSetDefinition
        try:
            FileSetDefinition.from_dict(file_set_dict)
        except (KeyError, ValueError) as e:
            raise HTTPException(400, {"error": "invalid_file_set", "detail": str(e)})

        job = JobModel(
            project_id=project_id,
            job_type="file_set_generation",
            reference_id=project_id,  # No file_set entity; use project as anchor
            status="pending",
            created_by=uuid.UUID(current_user["id"]),
        )
        session.add(job)
        await session.flush()

        run_file_set_generation_task.delay(file_set_dict, str(project_id), str(job.id))

        return {"job_id": str(job.id), "status": "pending"}
    ```
