<objective>
## Goal
Implement the masking bounded context with 7 strategy implementations, deterministic masking, chunked parallel processing via Celery, masking policy/rule management, side-by-side preview, and masking API endpoints.

## Purpose
Masking is the primary data protection feature. PII detection (Phase 5) identifies sensitive data; masking transforms it. This is a compliance requirement — HIPAA, GDPR, CCPA all mandate PII protection in test environments.

## Output
- Masking domain: MaskingPolicy, MaskingRule entities with strategy pattern
- 7 masking strategies: hash, redact, faker_replace, shuffle, nullify, FPE (FF1/FF3-1), partial_mask
- MaskingEngine with chunked parallel processing (10K rows/batch via Celery)
- Deterministic masking via HMAC-SHA256 with project-scoped salt
- Preview endpoint (side-by-side original vs masked)
- Masking API (policies, rules, preview, execute)
</objective>

## AC-1: 7 masking strategies produce correct output
```gherkin
Given a column value "john@email.com"
When each strategy is applied:
Then hash → deterministic SHA-256 hex (same input → same output with salt)
And redact → "XXXXX" (configurable redaction char)
And faker_replace → realistic fake email (e.g., "jane@example.com")
And shuffle → value from another row in same column
And nullify → NULL
And fpe → format-preserving encrypted value (same length, same character set)
And partial_mask → "j***@email.com" (configurable visible chars)
```

    2. Create domain/masking/value_objects.py (NO framework imports):
       - MaskingStrategy(Enum): HASH, REDACT, FAKER_REPLACE, SHUFFLE, NULLIFY, FPE, PARTIAL_MASK

    3. Create domain/masking/entities.py:
       - MaskingPolicy(AggregateRoot): project_id, name, description, is_default
       - MaskingRule(Entity): policy_id, column_id, match_pattern (dict|None), masking_type (MaskingStrategy), masking_config (dict), preserve_format (bool), deterministic (bool)

    4. Create domain/masking/repository.py:
       - MaskingRepository ABC: save_policy, get_policy, list_policies, add_rule, get_rules_by_policy

    5. Create domain/masking/events.py:
       - MaskingJobCompleted(DomainEvent): policy_id, table_count, row_count, duration_ms

    6. Create infrastructure/engine/masking_engine.py:
       - MaskingEngine class:
         - __init__(salt: str) — project-scoped salt for deterministic masking
         - mask_value(value, strategy, config) -> masked_value — single value
         - mask_dataframe(df, rules) -> df — entire DataFrame
         - mask_preview(df, rules, limit=5) -> list[dict] — side-by-side preview

       - Strategy implementations:
         - _hash(value, salt): HMAC-SHA256(salt + str(value)) → hex[:16] (deterministic)
         - _redact(value, config): replace with config.get("char", "X") * len(str(value))
         - _faker_replace(value, config): use Faker provider based on config.get("provider", "text")
         - _shuffle(values): random permutation of column values (batch operation)
           - WARNING: if column cardinality < 10, log warning "shuffle provides weak protection for low-cardinality column" and include warning in preview response <!-- audit-added: low cardinality warning -->
         - _nullify(value): return None
         - _fpe(value, salt, config): FF3-1 encryption preserving format (same length, charset)
           - Use ff3 library with AES key derived via HKDF (cryptography.hazmat.primitives.kdf.hkdf) from salt — NOT raw salt as key. Derive 128-bit AES key + separate 56-bit tweak from salt using different HKDF info strings. <!-- audit-added: secure key derivation -->
           - Alphabet: digits for numeric, alphanumeric for text
         - _partial_mask(value, config): show first N and last M chars, mask middle
           - config: {"show_first": 1, "show_last": 4, "mask_char": "*"}
           - "john@email.com" → "j***@email.com"

       - Chunked processing:
         - mask_table(connection, schema, table, rules, chunk_size=10000):
           - Read chunk_size rows via connector
           - Apply rules to each chunk
           - Yield masked chunks (generator for memory efficiency)

    Avoid: Implementing FPE from scratch — use the ff3 library.
    Avoid: Loading entire table into memory — chunk processing is mandatory.
  </action>
  <verify>

    - Hash is deterministic (same input + salt = same output)
    - FPE preserves format (same length as input)
    - Partial mask shows correct visible/hidden chars
    - Domain has zero framework imports
  </verify>
  <done>AC-1 satisfied (7 strategies). AC-2 satisfied (deterministic).</done>
