<objective>
## Goal
Ship `VSAMWriter` covering both fixed and variable record formats with full
mainframe-fidelity: EBCDIC CP037 / CP1140 character encoding, COMP-3
packed decimal, COMP big-endian binary, signed display numeric with EBCDIC
overpunch, and 4-byte big-endian RDW prefix for variable-length records.

## Purpose
This is the highest-risk plan of Phase 44. Mainframe-bound output that's
"almost right" is silently corrupt — a wrong nibble order or sign convention
won't error, it'll just produce data that fails downstream load. Ship with
byte-exact golden fixtures spanning every type × both code pages × both
record formats so format-fidelity bugs surface at unit-test time.

## Output
- `backend/app/infrastructure/writers/ebcdic_codec.py` — pure-stdlib wrapper around `codecs` for CP037 / CP1140 with explicit space-pad helpers
- `backend/app/infrastructure/writers/cobol_encoding.py` — COMP-3 / COMP encoders + overpunch helpers (no I/O, easy to unit-test)
- `backend/app/infrastructure/writers/vsam_writer.py` — `VSAMWriter` class handling both `VSAM_FIXED` and `VSAM_VARIABLE`
- `backend/tests/unit/test_cobol_encoding.py` — encoder unit tests (digit / sign / nibble)
- `backend/tests/unit/test_vsam_writer.py` — golden-byte writer tests
</objective>

## AC-1: EBCDIC codec module encodes ASCII strings to CP037 / CP1140
```gherkin
Given a Python string and a target EBCDIC encoding ("ebcdic_cp037" or "ebcdic_cp1140")
When ebcdic_codec.encode(text, encoding) is called
Then the returned bytes equal stdlib `text.encode("cp037")` / `text.encode("cp1140")`
And ebcdic_codec.space(encoding) returns the single space byte for that encoding
And ebcdic_codec.zero(encoding) returns the digit-zero byte for that encoding
And unknown encoding raises ValueError("Unsupported EBCDIC encoding: {value}")
```

## AC-2: COMP-3 packed-decimal encoder is byte-exact for known fixtures
```gherkin
Given an integer scaled to the schema's decimal_places and a (digits, signed) descriptor
When cobol_encoding.encode_comp3(scaled_int, digits, signed) is called
Then the bytes match these golden values:
  - encode_comp3(0, 3, False) == b"\x00\x0f"  # "0" + sign nibble 0xF
  - encode_comp3(123, 3, False) == b"\x12\x3f"
  - encode_comp3(123, 3, True) == b"\x12\x3c"  # +
  - encode_comp3(-123, 3, True) == b"\x12\x3d"  # -
  - encode_comp3(9950, 9, True) == b"\x00\x00\x00\x09\x95\x0c"  # 9 digits + sign = 10 nibbles = 5 bytes; left-pad missing
  - encode_comp3(99999, 5, False) == b"\x09\x99\x99\xf"[:3] is wrong — actual: b"\x09\x99\x9f" (5 digits + sign = 6 nibbles = 3 bytes)
And the returned byte count equals ceil((digits + 1) / 2)
And encoding a value that needs more than `digits` digits raises OverflowError
```

## AC-3: COMP binary encoder is big-endian two's complement
```gherkin
Given an integer and digit count
When cobol_encoding.encode_comp(value, digits, signed) is called
Then the byte length is determined by digit count (1-4 = 2, 5-9 = 4, 10-18 = 8)
And bytes are big-endian
And signed values use two's complement (e.g., -1 in 4 bytes = b"\xff\xff\xff\xff")
And signed=False rejects negative values with OverflowError
And values outside the byte-width range raise OverflowError
```

## AC-4: Display-signed overpunch encodes the sign onto the last digit (EBCDIC)
```gherkin
Given a signed integer and digit count
When cobol_encoding.encode_display_signed(value, digits, encoding) is called
Then the last byte's EBCDIC code is the overpunched digit:
  - For +0..+9: bytes "{", "A", "B", "C", "D", "E", "F", "G", "H", "I" (EBCDIC equivalents)
  - For -0..-9: bytes "}", "J", "K", "L", "M", "N", "O", "P", "Q", "R"
And the leading digits are zero-padded with EBCDIC '0' to total length = digits bytes.
```

## AC-5: VSAMWriter writes fixed-length records with no terminator
```gherkin
Given a FileSchemaDefinition with file_format=VSAM_FIXED and rows
When VSAMWriter.write(schema, rows, output_path) runs
Then each record is exactly schema.compute_record_length() bytes long
And no terminator bytes appear between records
And the total output file size equals N_rows × record_length
And every byte uses the schema's encoding (CP037 default, CP1140 alternative).
```

## AC-6: VSAMWriter writes variable-length records with a 4-byte big-endian RDW prefix
```gherkin
Given a FileSchemaDefinition with file_format=VSAM_VARIABLE and rows
When VSAMWriter.write(schema, rows, output_path) runs
Then each record is prefixed with a 4-byte header:
  - Bytes [0:2] = (record_length + 4) as big-endian uint16
  - Bytes [2:4] = 0x00 0x00
And the record payload immediately follows the RDW with no terminator
And the total file size = N_rows × (record_length + 4).
```

## AC-7: VSAMWriter respects schema-level COMP / COMP-3 / signed-display fields
```gherkin
Given a schema with mixed alphanumeric / numeric / decimal / packed_decimal / binary fields
When VSAMWriter renders a record:
  - alphanumeric fields are EBCDIC-encoded text right-padded with EBCDIC space
  - unsigned numeric fields are EBCDIC '0'-padded digits
  - signed numeric fields use display-signed overpunch on the last digit
  - decimal fields with comp_type=COMP_3 use encode_comp3 (decimal point implied)
  - decimal fields with comp_type=NONE and implied_decimal=True use display digits with EBCDIC '0' padding
  - numeric/decimal fields with comp_type=COMP use encode_comp
  - filler fields emit EBCDIC space × byte_length
  - REDEFINES fields are skipped on emit (target's bytes occupy the range)
And the rendered bytes for each field match its declared byte_length exactly.
```

## AC-8: Golden-byte fixtures cover both code pages and both record formats
```gherkin
Given a hand-built reference record covering:
  - PIC X(5) "HELLO"
  - PIC 9(5) = 12345
  - PIC S9(5) = -123  (overpunch)
  - PIC S9(5) COMP = -123
  - PIC S9(7)V99 COMP-3 = 9950 (= 99.50)
When the writer renders the record
Then the bytes equal a pre-computed golden value (asserted byte-for-byte)
And the same input rendered in CP1140 differs only at the Euro-sign codepoint
And the same input written in VSAM_VARIABLE prefixes the correct 4-byte RDW.
```

  <name>Task 2: COBOL encoders — COMP-3, COMP, display-signed overpunch</name>
  <files>backend/app/infrastructure/writers/cobol_encoding.py</files>
  <action>
    Create `cobol_encoding.py` exporting three pure functions:

    `def encode_comp3(value: int, digits: int, signed: bool) -> bytes`:
      Packed-decimal: each digit = 1 nibble (4 bits); the final nibble is the
      sign. Total nibbles = digits + 1. Bytes = ceil((digits + 1) / 2).
      - Sign nibble: 0xC for non-negative signed, 0xD for negative, 0xF for unsigned.
      - Algorithm:
        1. If not signed and value < 0: raise OverflowError.
        2. Compute abs(value)'s decimal digit string, left-pad with zeros to length `digits`.
        3. If that string is longer than `digits`: raise OverflowError.
        4. Sign nibble: 0xC if signed and value >= 0; 0xD if signed and value < 0; 0xF otherwise.
        5. Build a nibble list: digit nibbles + [sign nibble].
        6. If the count is odd, prepend a 0 nibble so the digits left-align in bytes.
        7. Pack two nibbles per byte (high nibble first).
      - Return bytes; length must equal ceil((digits + 1) / 2).

    `def encode_comp(value: int, digits: int, signed: bool) -> bytes`:
      Big-endian binary. Byte count by digit count: 1-4 → 2, 5-9 → 4, 10-18 → 8.
      - signed=False and value < 0 → OverflowError.
      - Use `int.to_bytes(length, "big", signed=signed)`; let stdlib raise OverflowError on range violations.

    `def encode_display_signed(value: int, digits: int, encoding: str) -> bytes`:
      Signed display numeric with overpunched sign on last digit.
      - encoding must be an EBCDIC code page (ebcdic_cp037 / ebcdic_cp1140).
      - Pad abs(value) zero-padded digit string to `digits`; raise OverflowError if too long.
      - Encode the first `digits-1` digits as plain EBCDIC '0'..'9'.
      - Compute the last byte from the last digit + sign:
        - Positive: {"0":"{", "1":"A","2":"B","3":"C","4":"D","5":"E","6":"F","7":"G","8":"H","9":"I"}
        - Negative: {"0":"}", "1":"J","2":"K","3":"L","4":"M","5":"N","6":"O","7":"P","8":"Q","9":"R"}
      - Look up the EBCDIC byte for the resulting character via `ebcdic_codec.encode`.
      - Return bytes; length must equal `digits`.

    All functions raise `ValueError` / `OverflowError` with descriptive messages; none do I/O.
  </action>

    Create `vsam_writer.py`:

    Imports: `pathlib.Path`,
    `app.domain.synthetic.file_schema.FileSchemaDefinition, FileFieldDefinition`,
    `app.domain.synthetic.value_objects.FileFormat`,
    `app.infrastructure.writers.base_writer.BaseFileWriter, write_atomic`,
    `app.infrastructure.writers.ebcdic_codec` (as `ebcdic`),
    `app.infrastructure.writers.cobol_encoding` (as `cobol`).

    Class `VSAMWriter(BaseFileWriter)`:
      `__init__(self)` — no configurable knobs; the schema carries everything.

      `@classmethod supported_formats(cls) -> set[FileFormat]`:
        return `{FileFormat.VSAM_FIXED, FileFormat.VSAM_VARIABLE}`.

      `get_extension(self) -> str`:
        return `"vsam"`.

      `validate_schema(self, schema) -> list[str]`:
        - `errors = list(super().validate_schema(schema))`
        - Reject non-VSAM formats explicitly.
        - Reject ASCII / UTF8 encodings (VSAM is EBCDIC); allow `ebcdic_cp037` / `ebcdic_cp1140`.
        - Reject `data_type == "alphanumeric"` with `signed=True` (nonsense combo).
        - Return errors.

      `_render_field(self, field, value, encoding, implied_decimal) -> bytes`:
        Branch on (data_type, comp_type, signed):

        - is_filler: return `ebcdic.space(encoding) * field.byte_length`.
        - value is None: same (null bytes are the EBCDIC space).
        - alphanumeric: `text = str(value)`; encode in EBCDIC; right-pad with
          EBCDIC space; truncate with warning if too long.
        - numeric / decimal display (comp_type == "none"):
            - For decimal with `implied_decimal=True`: scale to int (10**decimal_places),
              then encode digits zero-padded to `byte_length` in EBCDIC; if signed,
              use `cobol.encode_display_signed(scaled, field.byte_length, encoding)`
              (byte_length == digits for display signed). For unsigned, render the
              digit string left-padded with EBCDIC '0'.
            - For decimal with `implied_decimal=False` (rare for VSAM but allowed):
              render `f"{value:.{decimal_places}f}"` in EBCDIC zero-padded to byte_length.
            - For pure numeric: render int(value) zero-padded to digits in EBCDIC.
              If signed, use overpunch.
        - decimal / numeric with comp_type == "comp_3":
            - Scale: `int(round(value * (10 ** field.decimal_places)))`.
            - Call `cobol.encode_comp3(scaled, field.length, field.signed)`.
            - Assert length == field.byte_length; raise ValueError if not.
        - decimal / numeric with comp_type == "comp":
            - Scale as above (decimal places) — for integers decimal_places is 0.
            - Call `cobol.encode_comp(scaled, field.length, field.signed)`.
            - Assert length == field.byte_length.
        - binary type (data_type=="binary"): treat as COMP — same path.
        - packed_decimal type: treat as COMP-3 — same path.

      `write(self, schema, rows, output_path) -> Path`:
        1. `self._ensure_writable(schema, rows, output_path)`.
        2. record_length = `schema.compute_record_length()`.
        3. implied_decimal = `bool((schema.metadata or {}).get("implied_decimal", True))` — VSAM default is implied.
        4. encoding = schema.encoding (lowercased).
        5. is_variable = `schema.file_format == FileFormat.VSAM_VARIABLE.value`.
        6. Sort emitted fields by start_position; skip REDEFINES fields.
        7. Open `write_atomic(output_path, mode="wb")`:
           - For each row:
             - Build a bytearray initialized to `ebcdic.space(encoding) * record_length`.
             - For each emitted field, place `_render_field(...)` into the slice.
             - Assert `len(record) == record_length`.
             - If is_variable: prepend RDW: `((record_length + 4).to_bytes(2, "big") + b"\x00\x00")`.
             - Write `RDW + record` (or just `record` for fixed).
             - No record terminator either way.
        8. Return `output_path`.
  </action>
