<objective>
Fix 4 UX edge cases: SSE reconnection with backoff, NLP generation timeout feedback, notification persistence across refresh, and user-scoped onboarding tracking.
</objective>

<acceptance_criteria>
## AC-1: SSE Reconnection with Exponential Backoff
Given the useSSE hook, when a stream connection drops or errors:
- Automatically retry with exponential backoff (1s, 2s, 4s, 8s, max 30s)
- Max 5 retry attempts before giving up
- Show "Reconnecting..." state between retries
- Reset retry counter on successful reconnection
- Don't retry on AbortError (intentional disconnect) or terminal job status

## AC-2: NLP Synthetic Generation Timeout UX
Given the NLP prompt form, when a generation request is in-flight:
- Show elapsed time counter (e.g. "Generating... 12s")
- At 25s, show warning text "This is taking longer than usual"
- At 30s (backend timeout), show explicit timeout error message instead of generic failure
- AbortController with 35s client-side timeout as safety net

## AC-3: Notification Persistence
Given the notification store:
- Persist notifications to localStorage on every change
- Hydrate from localStorage on store initialization
- Key notifications by user ID from auth store (user-scoped)
- TTL: discard notifications older than 24 hours on hydration
- Max 50 notifications per user (existing cap)

## AC-4: User-Scoped Onboarding
Given the onboarding store uses global localStorage key "dw-onboarding-done":
- Scope the key by user ID: `dw-onboarding-${userId}`
- Read user ID from auth store on initialization
- Each user sees the onboarding wizard independently
- Fallback to global key if no user is authenticated
</acceptance_criteria>
