<acceptance_criteria>
## AC-1: Synthetic Quality — Real Implementation
Given a completed synthetic generation job, when GET /synthetic/configs/{config_id}/quality is called, then:
- composite_score is calculated from real column-level comparisons (not 0)
- column_scores contains per-column shape scores using statistical tests (KS test for numeric, chi-squared for categorical)
- column_pair_score reflects correlation preservation
- privacy_metrics.dcr_mean and dcr_min are computed from nearest-neighbor distance between real and synthetic rows
- If no generation has been run, return the current placeholder response with the explanatory note

Backend only — the frontend quality-report.tsx already renders this data correctly.

## AC-2: Compliance Download Auth Fix
Given the compliance report download endpoint uses `Depends(get_current_user)` which checks Bearer token OR cookie, and the frontend constructs a raw `<a href>` link:
- The link opens in a new tab where no Authorization header is sent
- Fix: Add the download URL through the api client (fetch with credentials) and create a blob download, OR add a short-lived download token query param

Implementation: Update `report-list.tsx` to use a fetch-based download with `credentials: "include"` that creates a blob URL, instead of a raw anchor link. This ensures httpOnly cookies are sent.

## AC-3: System Health Panel on Dashboard
Given the dashboard page, add a "System Status" card that:
- Calls GET /health (no auth required) on mount
- Shows database status (healthy/unhealthy) with green/red indicator
- Shows Redis status (healthy/unhealthy) with green/red indicator
- Shows overall status badge

Simple, lightweight — no polling.

## AC-4: User Profile Update
Given GET /auth/me exists but PUT /auth/me does not:
- Add PUT /auth/me endpoint accepting { full_name } to update the user's display name
- Uses get_current_user dependency, updates the UserModel record
- Returns updated user profile
