<objective>
## Goal
Upgrade the minimal job system into production-grade infrastructure: full job CRUD, SSE streaming for real-time progress, dead letter queue, checkpoint/resume, local filesystem storage backend, and a Jobs UI page with live progress bars.

## Purpose
Every async operation (discovery, generation, masking) needs reliable job tracking with real-time feedback. Users must see progress, errors, and be able to retry failed jobs. The storage backend enables generated data export. This is the operational backbone.

## Output
- Enhanced Job entity with checkpoint, DLQ support
- Job API endpoints (list, detail, cancel, retry, SSE stream)
- SSE streaming endpoint for real-time progress
- Storage abstraction with local filesystem implementation
- Jobs frontend page with live progress bars
- Prometheus metrics endpoint
</objective>

<acceptance_criteria>

## AC-1: Job API provides list, detail, cancel, and retry
```gherkin
Given async jobs created by discovery and generation tasks
When GET /api/v1/projects/{pid}/jobs is called
Then a paginated list of jobs returns (type, status, progress, timestamps)
And GET /jobs/{id} returns full detail including error_message and checkpoint
And POST /jobs/{id}/cancel updates status to cancelled
And POST /jobs/{id}/retry creates a new job from the failed job's config
```

## AC-2: SSE endpoint streams real-time job progress
```gherkin
Given a running job (discovery or generation)
When GET /api/v1/projects/{pid}/jobs/{id}/stream is called
Then an SSE connection is established (Content-Type: text/event-stream)
And progress updates are pushed as JSON events: {progress: N, status: "running", message: "..."}
And the stream closes when the job completes or fails
And the frontend useSSE hook receives updates and renders live progress bars
```

## AC-3: Storage backend saves and retrieves files
```gherkin
Given STORAGE_BACKEND is set to "local"
When StorageBackend.save(path, data) is called
Then the file is written to the configured local directory
And StorageBackend.load(path) returns the file contents
And StorageBackend.delete(path) removes the file
And StorageBackend.get_url(path) returns a download URL or path
```

## AC-4: Jobs UI page shows live progress and error details
```gherkin
Given an authenticated user visits /projects/{id}/jobs
When the page loads
Then a list of jobs displays with type, status badge, progress bar, timestamps
And clicking a job shows detail: progress breakdown, error message, log entries
And running jobs show animated progress bars updated via SSE
And failed jobs show "Retry" button
```
