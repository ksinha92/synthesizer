<objective>
## Goal
Implement the schema discovery engine and 4-layer PII detection pipeline — so the platform can automatically introspect any connected database and identify sensitive data columns with confidence scoring.

## Purpose
Discovery + PII detection is the core AI value proposition. Everything downstream (masking, subsetting, compliance) depends on knowing what data exists and which columns contain PII. This is the feature that differentiates DataWrangler from manual TDM tools.

## Output
- `backend/app/domain/discovery/` — Discovery bounded context (Schema, Table, Column, Relationship entities + PIIType, PIIConfidence value objects)
- `backend/app/infrastructure/ai/pii_detector.py` — 4-layer pipeline: regex → Presidio+spaCy → heuristics → LLM fallback
- `backend/app/infrastructure/messaging/discovery_tasks.py` — Celery task with 3-retry exponential backoff
- `backend/app/api/v1/discovery.py` — Discovery endpoints (run, results, PII, override)
- Alembic migration for discovery tables
</objective>

<acceptance_criteria>

## AC-1: Discovery domain entities and repository persist schema metadata
```gherkin
Given a connection to a PostgreSQL database
When the SchemaDiscoveryService runs introspection via the connector
Then DiscoveredSchema, DiscoveredTable, and DiscoveredColumn entities are created
And each column has data_type, is_nullable, is_primary_key, stats (cardinality, null_percentage)
And the entities are persisted via the DiscoveryRepository
And a DiscoveryCompleted domain event is emitted
```

## AC-2: 4-layer PII detection pipeline produces weighted confidence scores
```gherkin
Given a list of DiscoveredColumn entities with sample data
When the PIIDetectionService runs the 4-layer pipeline
Then Layer 1 (regex) detects SSN, credit card, phone, email, IP patterns
And Layer 2 (Presidio+spaCy) detects PERSON, LOCATION, DATE_TIME entities
And Layer 3 (heuristics) matches column names against known PII patterns
And Layer 4 (LLM) is invoked ONLY when combined confidence from Layers 1-3 is < 0.4
And each column receives a weighted pii_confidence score
And columns with confidence >= 0.65 are auto-classified
And columns with confidence 0.4-0.65 are flagged as needs-review
```

## AC-3: Discovery runs as async Celery task with retry and progress
```gherkin
Given a user triggers POST /api/v1/projects/{pid}/discovery/run
When the discovery Celery task executes
Then it runs introspection → PII detection → relationship inference → persist
And progress is trackable via the job system (job record created)
And on transient failure, the task retries with exponential backoff (30s/60s/120s, max 3)
And a DiscoveryCompleted event is emitted on success
```

## AC-4: Discovery API endpoints return schema tree and PII classifications
```gherkin
Given a completed discovery run for a project
When GET /api/v1/projects/{pid}/discovery/results is called
Then the response contains the full schema tree (schemas → tables → columns)
And GET /api/v1/projects/{pid}/discovery/pii returns PII classifications with confidence
And PUT /api/v1/projects/{pid}/discovery/columns/{id}/classification overrides PII type
And all endpoints require authentication
```

  <files>

  <action>
    1. Add dependencies to pyproject.toml:
       - presidio-analyzer>=2.2.0 (Microsoft Presidio PII detection)
       - spacy>=3.7.0 (NER backend for Presidio)
       - NOTE: spaCy model (en_core_web_lg) must be downloaded separately: python -m spacy download en_core_web_lg

    2. Create backend/app/infrastructure/ai/pii_detector.py:
       - PIIDetectionService class:
         - __init__(llm_provider=None) — LLM provider is optional (graceful degradation)
         - Initialize Presidio AnalyzerEngine ONCE in __init__ (not per-column — spaCy model load is expensive) <!-- audit-added: performance -->
         - detect(columns: list[DiscoveredColumn]) -> list[DiscoveredColumn] — runs pipeline on each column, returns with pii_type, pii_confidence, classification set

       - Layer 1 — Regex Detection:
         - _detect_regex(column) -> tuple[PIIType|None, float]:
         - Patterns: SSN (XXX-XX-XXXX), credit card (Luhn-valid 13-19 digits), phone (various formats), email (RFC-ish), IP (v4/v6)
         - Runs against column sample_values
         - Returns (detected_type, confidence) — high confidence (0.9+) for regex matches

       - Layer 2 — Presidio + spaCy NER:
         - _detect_presidio(column) -> tuple[PIIType|None, float]:
         - Initialize Presidio AnalyzerEngine with spaCy NER (en_core_web_lg)
         - Run analyzer on concatenated sample_values
         - Map Presidio entity types (PERSON, LOCATION, DATE_TIME, etc.) to PIIType enum
         - Returns (detected_type, confidence) from Presidio score

       - Layer 3 — Column Name Heuristics:
         - _detect_heuristics(column) -> tuple[PIIType|None, float]:
         - Match column_name against known PII patterns:
           - email/e_mail/email_address → EMAIL (0.7)
           - ssn/social_security/social_sec → SSN (0.8)
           - phone/mobile/cell/telephone → PHONE (0.7)
           - first_name/last_name/full_name/name → PERSON_NAME (0.6)
           - address/street/city/zip/postal → ADDRESS (0.6)
           - dob/date_of_birth/birth_date → DATE_OF_BIRTH (0.7)
           - card_number/credit_card/cc_num → CREDIT_CARD (0.8)
           - ip/ip_address → IP_ADDRESS (0.7)
         - Case-insensitive matching
         - Returns (detected_type, confidence)

       - Layer 4 — LLM Classification (FALLBACK ONLY):
         - _detect_llm(column) -> tuple[PIIType|None, float]:
         - ONLY invoked when max confidence from Layers 1-3 < 0.4
         - If no LLM provider configured: skip, log warning, return (NONE, 0.0)
         - Input sanitization before prompt construction: <!-- audit-added: prompt injection prevention -->
           1. Strip all control characters (\\x00-\\x1f) from column name and sample values
           2. Truncate column name to 100 chars, each sample value to 200 chars
           3. Limit to 3 sample values in prompt
           4. Wrap user-supplied data in XML tags to separate from instructions: <column_name>...</column_name> <samples>...</samples>
         - Prompt: structured prompt with sanitized inputs asking for PII classification
         - Parse structured response into PIIType + confidence
         - Circuit breaker via pybreaker — if LLM fails 5 times, stop calling for this batch

       - Weighted Scoring:
         - _combine_scores(results: list[tuple[PIIType, float, str]]) -> tuple[PIIType, PIIConfidence, Classification]:
         - Take highest-confidence detection across all layers
         - If confidence >= 0.65 → AUTO_CLASSIFIED
         - If 0.4 <= confidence < 0.65 → NEEDS_REVIEW
         - If confidence < 0.4 → NONE (or invoke Layer 4)
         - Build PIIConfidence value object with score, detector layer name, details dict

    Avoid: Running LLM on every column — only when Layers 1-3 are inconclusive (< 0.4).
    Avoid: Blocking on spaCy model download — detect if model missing and raise clear error.
    Avoid: Storing raw sample values in PII detector — work with what's already in DiscoveredColumn.
  </action>
