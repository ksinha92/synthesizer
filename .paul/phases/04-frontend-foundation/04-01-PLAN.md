<objective>
## Goal
Initialize the Next.js 14 frontend with hybrid design system (shadcn/ui + Tailwind primary, Ant Design Table/Tree CSS-scoped), dark/light/system theme, AppShell layout (collapsible sidebar + header + content), Zustand stores, API hook, and test infrastructure — so all subsequent UI phases have a working foundation.

## Purpose
Phase 8 builds pages on this foundation. The hybrid design system, theme, and AppShell must be solid before page development starts. Getting the shadcn + Ant Design CSS scoping right early prevents painful refactoring later.

## Output
- `frontend/` — Next.js 14 project with App Router, shadcn/ui, Tailwind CSS
- Theme system with dark/light/system toggle + CSS variable tokens
- AppShell: collapsible sidebar (240px/64px), header (56px), content area (max-width 1440px)
- Zustand stores (theme, auth), useApi hook
- Login page (SSO redirect)
- Jest + Playwright scaffolding
</objective>

       - :root CSS variables for light theme tokens
       - .dark CSS variables for dark theme tokens
       - Ant Design CSS isolation using @layer: <!-- audit-added: robust CSS scoping -->
         ```css
         /* Use CSS layers for clean precedence without breaking layout */
         @layer tailwind, ant;
         @layer tailwind {
           @tailwind base;
           @tailwind components;
           @tailwind utilities;
         }
         /* Ant Design styles in .ant-scoped containers get their own layer */
         .ant-scoped {
           /* Ant Design renders within this wrapper. Its styles take precedence
              within this container because the ant layer is declared after tailwind. */
         }
         ```
         NOTE: Do NOT use `all: revert` — it reverts layout properties (display, position) and breaks Ant Design components. CSS @layer gives clean precedence without side effects.
       - Import Inter and JetBrains Mono font-face declarations

    4. Create frontend/src/components/theme/theme-provider.tsx:
       - Wraps next-themes ThemeProvider with attribute="class", defaultTheme="system", enableSystem
       - Provides dark/light/system switching via class attribute on <html>
       - Syncs Ant Design ConfigProvider theme tokens to match active theme

    5. Create frontend/src/components/theme/theme-toggle.tsx:
       - Three-way toggle button: Light (Sun icon) / Dark (Moon icon) / System (Monitor icon)
       - Uses useTheme() from next-themes
       - Renders as shadcn DropdownMenu or toggle group
       - Persisted via next-themes (localStorage)

    6. Create frontend/src/app/layout.tsx:
       - Root layout with ThemeProvider wrapping
       - Inter font as default, JetBrains Mono as mono
       - Meta tags, favicon, title "DataWrangler"
       - Import globals.css
       - Wrap children in React ErrorBoundary (catch unhandled errors, show "Something went wrong" with retry) <!-- audit-added -->
       - Wrap children in Suspense boundary with loading fallback <!-- audit-added -->

    7. Create frontend/src/lib/utils.ts:
       - cn() utility (clsx + tailwind-merge)
       - Standard shadcn helper

    8. Create frontend/components.json (shadcn config):
       - Style: "default", RSC: true, Tailwind CSS variables: true
       - Aliases: @/components, @/lib, @/hooks, @/stores

    9. Create frontend/next.config.js with security headers: <!-- audit-added: CSP -->
       - Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-eval' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self' http://localhost:8000 http://localhost:8080; font-src 'self' data:
       - X-Frame-Options: DENY
       - X-Content-Type-Options: nosniff
       - Referrer-Policy: strict-origin-when-cross-origin
       - NOTE: CSP can be relaxed per-environment. The connect-src must include the API and Keycloak URLs.

    10. Create frontend/Dockerfile:

    Avoid: Using Ant Design's global CSS reset — it will conflict with Tailwind.

       - State: user (null | {id, email, role, full_name}), isAuthenticated
       - Actions: setUser, logout, loadUser (calls GET /api/v1/auth/me)
       - Token storage: use httpOnly cookies set by backend (Phase 2 callback already returns tokens). Do NOT store tokens in localStorage — XSS can exfiltrate localStorage tokens. The useApi hook sends credentials: "include" to attach cookies automatically. <!-- audit-added: XSS mitigation -->
       - If backend cookie approach isn't feasible, use in-memory state only (lost on refresh, requires re-auth) — still safer than localStorage
       - On init: call GET /api/v1/auth/me with credentials: "include" to check if session cookie is valid

    2. Create frontend/src/stores/theme-store.ts (Zustand):
       - Minimal — next-themes handles most theme state
       - Stores sidebar collapsed state (persisted in localStorage)
       - Stores notification preferences (placeholder)

    3. Create frontend/src/hooks/use-api.ts:
       - Custom hook wrapping fetch:
         - Uses credentials: "include" on all requests to send httpOnly session cookies <!-- audit-added -->
         - Base URL from NEXT_PUBLIC_API_URL env var (default http://localhost:8000)
         - On 401 response: clear auth store, redirect to /login (preserving intended URL in query param ?redirect=) <!-- audit-added: redirect preservation -->
         - Returns { data, error, loading, mutate } pattern
         - Typed: useApi<T>(url, options) -> { data: T | null, ... }
       - Methods: get, post, put, delete

    4. Create frontend/src/app/(auth)/login/page.tsx:
       - Clean login page with DataWrangler logo
       - "Sign in with SSO" button → redirects to NEXT_PUBLIC_API_URL + /api/v1/auth/sso/login
       - Before redirect: store current URL (from ?redirect= query param or window.location) in sessionStorage so callback can restore it <!-- audit-added: redirect preservation -->
       - Below button: "For development, use Keycloak at localhost:8080"
       - No AppShell wrapper (standalone layout)
       - After SSO callback returns: read redirect URL from sessionStorage, navigate there (default /)

    5. Create frontend/jest.config.ts:
       - Next.js jest configuration with SWC transform

       - Setup file for testing-library

    6. Create frontend/playwright.config.ts:
