<acceptance_criteria>

## AC-1: Orchestrator topo-sorts by cross-file FKs
```gherkin
Given a FileSetDefinition with 3 schemas A, B, C and CrossFileFK(B→A, C→B)
When orchestrator.plan() runs
Then the generation order is [A, B, C]
And cycles raise ValueError.
```

## AC-2: Child generation references parent PKs
```gherkin
Given a FK declaring child.fkcol references parent.id
When the orchestrator generates rows for `child`
Then every non-null `fkcol` value appears in the previously-generated `parent` rows' `id` column.
```

## AC-3: Zip bundle contains every file + a manifest
```gherkin
Given N files written by the orchestrator
When bundle_files(files, manifest, output_path) runs
Then the zip contains N + 1 entries: each file at its declared name + "manifest.json"
And manifest.json captures: file_set name, per-file (name, format, row_count, byte_count, sha256)
And the bundle is written atomically (via write_atomic).
```

## AC-4: Celery task runs orchestrator end-to-end
```gherkin
Given a FileSetDefinition stored in metadata (or built inline for tests)
When run_file_set_generation_task is invoked
Then it generates all files, bundles them, updates the JobModel status to "completed"
And stores the zip path in result_summary["bundle_path"].
```

## AC-5: Download endpoint streams the zip
```gherkin
Given a completed file-output job whose result_summary contains "bundle_path"
When GET /api/v1/projects/{project_id}/synthetic/jobs/{job_id}/file-output is called
Then the response Content-Type is "application/zip"
And Content-Disposition has filename matching the file_set name.
```

    Create `file_set_orchestrator.py`:

    Imports: `pathlib.Path`, `FileSchemaDefinition`, `FileSetDefinition`, `CrossFileFK`,
    `FakerEngine` (`from app.infrastructure.engine.faker_engine import FakerEngine`),
    `WriterRegistry.get_writer` (`from app.infrastructure.writers.registry import get_writer`),
    `SyntheticConfig` from `app.domain.synthetic.entities`,
    `collections.defaultdict, deque`.

    Class `FileSetOrchestrator`:
      `__init__(self, file_set: FileSetDefinition, row_counts: dict[str, int] | None = None, seed: int | None = None)`:
        - Store inputs; row_counts maps schema name → row count (defaults to 100 each).

      `plan(self) -> list[str]`:
        - Kahn's algorithm on (target_file → source_file) edges from foreign_keys.
        - Source depends on target — generate target first.
        - Detect cycles → raise ValueError.

      `async generate(self, output_dir: Path) -> list[Path]`:
        - For each schema in topo order:
          - Build a SyntheticConfig with the schema's fields rendered as `columns`
            list (FileFieldDefinition → dict with column_name + data_type).
          - Build pk_pools from previously-generated schemas keyed by field name.
          - Run FakerEngine.generate; the engine sees pk_pools via fk_references
            on the column dicts.
          - Resolve writer via `get_writer(FileFormat(schema.file_format))`.
          - Output file = output_dir / (schema.output_filename or f"{schema.name}.{writer.get_extension()}").
          - writer.write(schema, rows, output_path).
          - Store output_path; remember the row dicts for downstream FK pools.

      Returns the list of written file paths.

    Note: the simple FK propagation here uses field name matching across schemas
    (e.g., if customer.id is the PK and order.customer_id has fk_reference
    pointing to "customers"."id", the engine looks up generated customer rows
    by name "customers" and pulls "id" values). That matches the existing
    FakerEngine FK behavior — no engine change needed.
  </action>

    1. Append `run_file_set_generation_task(file_set_dict, project_id, job_id)`
       to `synthetic_tasks.py`. Inputs come in as a JSON-serializable dict
       (FileSetDefinition.to_dict()).

       Steps:
       - asyncio.run an inner coroutine.
       - Load JobModel; mark status="running" with started_at.
       - file_set = FileSetDefinition.from_dict(file_set_dict).
       - Create a temp dir; orchestrator.generate(temp_dir).
       - bundle_files(...) → store the zip under SAMPLE_OUTPUT_DIR / job_id / "{file_set.name}.zip".
       - Update JobModel: status="completed", result_summary={"bundle_path": str(path), "file_count": N}.
       - On failure: status="failed", error_message captured.

    2. Append a download endpoint to `synthetic.py`:

       ```python
       @router.get("/jobs/{job_id}/file-output")
       async def download_file_output(
           project_id: uuid.UUID,
           job_id: uuid.UUID,
           current_user: dict = Depends(get_current_user),
           session: AsyncSession = Depends(get_session),
       ):
           from fastapi.responses import FileResponse
           from app.infrastructure.persistence.models.job import JobModel
           from sqlalchemy import select as sa_select

           job = (await session.execute(sa_select(JobModel).where(JobModel.id == job_id))).scalar_one_or_none()
           if not job:
               raise HTTPException(404, {"error": "not_found"})
           if job.status != "completed":
               raise HTTPException(409, {"error": "not_ready", "detail": f"job status={job.status}"})
           path = (job.result_summary or {}).get("bundle_path")
           if not path:
               raise HTTPException(404, {"error": "no_bundle"})
           p = Path(path)
           if not p.exists():
               raise HTTPException(410, {"error": "bundle_missing", "detail": "Bundle was removed from storage"})
           return FileResponse(
               p,
               media_type="application/zip",
               filename=p.name,
           )
       ```

       The endpoint is project-scoped via the existing synthetic router prefix
       (`/projects/{project_id}/synthetic`).

       Add `from pathlib import Path` if not already imported.
