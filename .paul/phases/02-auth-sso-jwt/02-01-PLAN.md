<objective>
## Goal
Implement SSO authentication (OIDC) with JWT fallback for service accounts, auth middleware, and user session management — so the platform has secure identity before any data operations are built.

## Purpose
Every subsequent feature (connections, discovery, masking) requires knowing who the user is. Auth must be in place before any API endpoints handle real data. SSO integrates with Ameritas corporate identity; JWT covers CI/CD and automated workflows.

## Output
- `backend/app/infrastructure/auth/oidc.py` — OIDC provider integration (authlib)
- `backend/app/infrastructure/auth/jwt.py` — JWT token creation/validation for service accounts
- `backend/app/infrastructure/auth/dependencies.py` — FastAPI dependency for auth injection
- `backend/app/api/v1/auth.py` — Auth endpoints (SSO login, callback, token, refresh)
- Updated user model with auth-specific fields
- Alembic migration for auth schema changes
</objective>

<acceptance_criteria>

## AC-1: OIDC login flow redirects to provider and handles callback
```gherkin
Given the backend is running with OIDC configuration
When a user visits GET /api/v1/auth/sso/login
Then they are redirected to the configured OIDC provider authorization URL
And the redirect includes client_id, redirect_uri, scope=openid+email+profile, and state parameter
```

## AC-2: OIDC callback creates or updates user and returns session token
```gherkin
Given the OIDC provider redirects back to GET /api/v1/auth/sso/callback with a valid authorization code
When the backend exchanges the code for tokens and extracts user info
Then a user record is created (if new) or updated (if existing) in the database
And a signed JWT session token is returned (httponly cookie or JSON body)
And the token contains user_id, email, role, and expiry
```

## AC-3: JWT service account token endpoint works for CI/CD
```gherkin
Given a service account with a valid API key
When POST /api/v1/auth/token is called with the API key
Then a signed JWT is returned with service_account role and configurable expiry
And the token can be used to authenticate subsequent API requests via Authorization header
```

## AC-5: OIDC state parameter prevents CSRF <!-- audit-added -->
```gherkin
Given a user initiates SSO login and receives a state parameter
When an attacker crafts a callback URL with a different or missing state value
Then the callback returns 400 Bad Request with "invalid_state" error
And the authorization code is NOT exchanged
```

## AC-6: Refresh tokens are revocable <!-- audit-added -->
```gherkin
Given a user has a valid refresh token
When the user's token_version is incremented (e.g., via password change or admin action)
Then the existing refresh token is rejected on next use with 401
And a new login is required
```

## AC-4: Auth dependency protects API routes
```gherkin
Given an API route decorated with the auth dependency
When a request arrives without a valid token (missing, expired, or tampered)
Then the response is 401 Unauthorized with a structured error body
And when a request arrives with a valid token
Then the current user is injected into the route handler
```

    1. Add dependencies to pyproject.toml:
       - authlib>=1.3.0 (OIDC/OAuth2 client)
       - httpx>=0.27.0 (async HTTP for token exchange)
       - python-jose[cryptography]>=3.3.0 (JWT creation/validation)
       - slowapi>=0.1.9 (rate limiting for auth endpoints) <!-- audit-added -->

    2. Update backend/app/config.py — add auth settings:
       - OIDC_ISSUER_URL: str = "" (e.g., https://ameritas.okta.com)
       - OIDC_CLIENT_ID: str = ""
       - OIDC_CLIENT_SECRET: str = ""
       - OIDC_REDIRECT_URI: str = "http://localhost:8000/api/v1/auth/sso/callback"
       - OIDC_SCOPES: str = "openid email profile"
       - JWT_ALGORITHM: str = "HS256"
       - JWT_ACCESS_TOKEN_EXPIRE_MINUTES: int = 60
       - JWT_REFRESH_TOKEN_EXPIRE_MINUTES: int = 10080 (7 days)
       - SERVICE_ACCOUNT_API_KEYS: list[str] = [] (comma-separated valid API keys — NOTE: store hashed in production, compare with hmac.compare_digest) <!-- audit-added -->
       - AUTH_RATE_LIMIT: str = "10/minute" (rate limit for auth endpoints) <!-- audit-added -->

    3. Create backend/app/domain/shared/errors.py:
       - AuthenticationError(Exception) — invalid credentials, expired token
       - AuthorizationError(Exception) — insufficient permissions
       - These are domain errors, no framework imports.

    4. Create backend/app/infrastructure/auth/oidc.py:
       - OIDCProvider class:
         - __init__(settings: Settings) — configures authlib AsyncOAuth2Client
         - get_authorization_url() -> tuple[str, str] — returns (url, state). State must be a cryptographically random value (secrets.token_urlsafe(32)), stored in Redis with 10-minute TTL keyed by state value <!-- audit-added: CSRF protection -->
         - exchange_code(code: str, state: str) -> dict:
           - FIRST: validate state param against Redis (retrieve + delete in one operation). Reject if missing/expired. <!-- audit-added: CSRF validation -->
           - Exchange auth code for tokens via provider's token endpoint
           - Verify id_token signature against provider's JWKS endpoint (authlib handles this via metadata discovery) <!-- audit-added: id_token verification -->
           - Extract user_info from verified id_token claims (sub, email, name)
           - Return user_info dict
         - Uses OIDC discovery endpoint (.well-known/openid-configuration) for provider URLs
       - Handle errors: invalid code, expired/missing state (CSRF rejection), provider unreachable, id_token signature invalid
       - If OIDC_ISSUER_URL is empty, raise a clear error on usage (not on import — allows dev without SSO configured)

    5. Create backend/app/infrastructure/auth/jwt.py:
       - create_access_token(user_id: UUID, email: str, role: str) -> str
         - Signs JWT with SECRET_KEY, includes sub, email, role, exp, iat
       - create_refresh_token(user_id: UUID, token_version: int) -> str
         - Longer expiry, includes sub, exp, iat, type=refresh, ver=token_version
         - token_version is stored on UserModel — incrementing it invalidates all existing refresh tokens for that user <!-- audit-added: revocation mechanism -->
       - decode_token(token: str) -> dict
         - Validates signature, expiry. Raises AuthenticationError on failure.
         - For refresh tokens: also validate token_version against user's current version — reject if stale <!-- audit-added: version check -->
       - create_service_account_token(api_key: str) -> str
         - Validates api_key against SERVICE_ACCOUNT_API_KEYS using hmac.compare_digest (constant-time comparison) <!-- audit-added: timing attack prevention -->
         - Returns JWT with role=service_account
         - Raises AuthenticationError if key invalid

    6. Update backend/app/infrastructure/persistence/models/user.py: <!-- audit-added -->
       - Add token_version: Mapped[int] = mapped_column(Integer, default=0, nullable=False)
         (Incrementing this invalidates all refresh tokens for the user — revocation mechanism)
       - Add last_login_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True)

    7. Create backend/alembic/versions/002_add_auth_fields.py: <!-- audit-added -->
       - Add token_version (integer, default 0) to users table
       - Add last_login_at (timestamp with timezone, nullable) to users table

    8. Update container.py:
       - Add OIDCProvider as singleton provider
       - Wire to auth module

    Avoid: Storing tokens in plaintext in the database (tokens are stateless JWTs).
    Avoid: Using symmetric JWT signing for production — note TODO for RSA/ES256 in production.

  <name>Task 2: Create auth API endpoints and FastAPI auth dependency</name>
  <files>

  <action>
    1. Create backend/app/infrastructure/auth/dependencies.py:
       - get_current_user(request: Request) -> dict:
         - Extract token from Authorization header (Bearer) or httponly cookie
         - Decode with jwt.decode_token()
         - Query UserModel by user_id from token claims
         - Return user dict (id, email, role)
         - Raise HTTPException(401) if token missing, invalid, or expired
         - Raise HTTPException(401) if user not found or inactive
       - require_role(required_role: str) -> Depends:
         - Returns a dependency that checks current_user.role against required_role
         - Raise HTTPException(403) if insufficient
       - get_optional_user(request: Request) -> dict | None:
         - Same as get_current_user but returns None instead of raising 401

    2. Create backend/app/api/v1/auth.py with routes:
       - GET /api/v1/auth/sso/login:
         - Calls OIDCProvider.get_authorization_url()
         - Returns RedirectResponse to provider
       - GET /api/v1/auth/sso/callback:
         - Receives code + state params
         - Calls OIDCProvider.exchange_code()
         - Creates/updates user in DB (upsert by sso_subject_id)
         - Creates access + refresh tokens
         - Returns JSON with tokens (or sets httponly cookies)
       - POST /api/v1/auth/token:
         - Accepts {"api_key": "..."} body
         - Validates against SERVICE_ACCOUNT_API_KEYS
         - Returns JWT with service_account role
         - Returns 401 if invalid key
       - POST /api/v1/auth/refresh:
         - Accepts {"refresh_token": "..."} body
         - Validates refresh token
         - Issues new access token
         - Returns 401 if refresh token invalid or expired
       - GET /api/v1/auth/me:
         - Requires auth (get_current_user dependency)
         - Returns current user profile (id, email, full_name, role)

    3. Update backend/app/api/v1/__init__.py:
       - Include auth_router in api_router

    4. Add rate limiting to auth endpoints (slowapi): <!-- audit-added -->
       - /auth/token: 10 requests/minute per IP
       - /auth/refresh: 10 requests/minute per IP
       - /auth/sso/login: 20 requests/minute per IP
       - Return 429 Too Many Requests with Retry-After header when exceeded

    5. Add structured audit logging for all auth events: <!-- audit-added -->
       - Log with structlog on every auth action: event_type, user_id (if known), ip_address, timestamp, success/failure
       - Events: sso_login_initiated, sso_callback_success, sso_callback_failure, token_created, token_refresh, token_invalid, auth_denied
       - NEVER log token values, secrets, or API keys — only event metadata

    All error responses must be structured JSON: {"error": "error_code", "detail": "human message"}

    Avoid: Logging tokens or secrets in any log output.
    Avoid: Returning password hashes or internal IDs in error responses.
  </action>
