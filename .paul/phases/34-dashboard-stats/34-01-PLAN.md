<objective>
Wire all dashboard and project detail stat cards to real API data, replace hardcoded PII heatmap and donut data with API-fetched values, and connect job SSE events to the notification store so users get notified of job completions/failures.
</objective>

<acceptance_criteria>
## AC-1: Dashboard Stats from API
Given the dashboard loads, when API responds, then all 4 stat cards show real counts: projects (from /projects), active jobs (from /jobs?status=running), tables masked (from /masking/stats or count), jobs today (from /jobs?created_today). Fallback to 0 on error.

## AC-2: Project Detail Stats
Given a project detail page, when loaded, then stat cards show real counts: connections count, discovery schemas count, masking policies count, synthetic configs count. All fetched from respective API endpoints.

## AC-3: PII Heatmap + Donut from API
Given discovery data exists, when dashboard loads, then PII heatmap and donut chart use real data fetched from /discovery/stats or aggregated from schema data. Fallback to empty/sample data if no discovery data.

## AC-4: Job Events → Notifications
Given a job completes or fails, when the jobs page is active with SSE, then a notification is added to the notification store (type: completed/failed, message includes job type).
</acceptance_criteria>

<tasks>
<task type="auto">
  <name>Wire dashboard stats + notifications</name>
  <action>
    1. Dashboard page: fetch all 4 stats in parallel — projects count, active jobs count (status=running), masking stats, today's jobs count. Use Promise.allSettled for resilience.
    2. Project detail page: fetch connection count, schema count, masking policy count, synthetic config count for the specific project. Display real numbers instead of "—".
    3. Dashboard PII data: attempt to fetch aggregated PII stats from API. If available, pass to heatmap and donut. If not available (no discovery yet), show current sample data with a note.
    4. Job SSE → notifications: in the jobs page or a global hook, when SSE receives a job status change to "completed" or "failed", call addNotification on the notification store.
  </action>
</task>
</tasks>

- DO NOT modify stores beyond what's needed for data fetching
- Graceful fallback: if any API call fails, show 0 or "—", never crash
</boundaries>

- Notifications fire on job completion (when SSE active)
