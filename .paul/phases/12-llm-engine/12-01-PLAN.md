<objective>
## Goal
Build the LLM synthetic engine that converts natural language prompts into structured generation plans, then executes them via Faker/Statistical engines — the intelligent "describe what you need" interface.

## Purpose
This is the AI differentiator. Instead of manually configuring tables and columns, users describe data in plain English. The LLM translates intent to config, the user reviews/edits, then generation executes. "Generate 1000 insurance claims where 20% are auto claims with amounts $500-$50K."

## Output
- LLMEngine: prompt → generation plan → execution
- NLP generation API endpoint
- Frontend: NLP prompt textarea, editable generation plan, execute button
- LLM engine card enabled in frontend
</objective>

<acceptance_criteria>

## AC-1: LLM parses NLP prompt into structured generation plan
```gherkin
Given a natural language prompt like "Generate 5000 insurance claims where 60% health, 30% auto, 10% property"
When LLMEngine.create_plan(prompt, schema_metadata) is called
Then the LLM produces a structured plan: table name, row count, column configs
  (categorical distributions, numeric ranges, FK references, constraints)
And the plan is editable JSON that maps to SyntheticConfig
```

## AC-2: Generation plan executes via Faker engine
```gherkin
Given an approved generation plan from the LLM
When LLMEngine.generate(config, schema) is called
Then it converts the plan into Faker/Statistical engine column configs
And delegates actual generation to FakerEngine (or StatisticalEngine)
And returns generated rows matching the plan's distributions and constraints
```

## AC-3: NLP generation API endpoint works end-to-end
```gherkin
Given an authenticated user
When POST /api/v1/projects/{pid}/synthetic/nlp-generate is called with {prompt, connection_id}
Then the LLM creates a plan (returned synchronously for review)
And POST /api/v1/projects/{pid}/synthetic/nlp-execute with {plan, connection_id} executes generation
And the execution returns a job_id (async via Celery)
```

## AC-4: Frontend has NLP prompt interface with editable plan
```gherkin
Given the user selects the LLM engine
When they type a prompt and click "Generate Plan"
Then the plan appears as editable JSON/form below the prompt
And the user can modify the plan before clicking "Execute"
And execution dispatches async generation job
```

         - Build context prompt with available tables/columns from schema_metadata
         - Ask LLM to produce structured JSON plan:
           {
             "tables": [{
               "table_name": "claims",
               "row_count": 5000,
               "columns": [
                 {"name": "type", "strategy": "categorical", "distribution": {"health": 0.6, "auto": 0.3, "property": 0.1}},
                 {"name": "amount", "strategy": "range", "min": 500, "max": 50000, "distribution": "lognormal"},
                 {"name": "is_suspicious", "strategy": "boolean", "true_pct": 0.15},
                 {"name": "policyholder_id", "strategy": "fk", "ref_table": "policyholders", "ref_column": "id"}
               ]
             }]
           }
         - Validate plan against schema (table/column names exist)
         - SECURITY: Validate all column strategies against allowlist: ["categorical", "range", "boolean", "fk", "text", "faker", "null"]. Reject any plan with unknown strategies — prevents code injection via LLM-generated configs. <!-- audit-added -->
         - Include token usage from LLM call in the returned plan metadata (for cost visibility) <!-- audit-added -->
         - Return plan dict

       - generate() implementation:
         - Convert LLM plan columns into Faker-compatible config:
           - "categorical" → weighted random.choices
           - "range" → random uniform/lognormal within bounds
           - "boolean" → weighted boolean
           - "fk" → FK reference (same as Faker)
           - "text" → Faker text provider
         - Delegate to FakerEngine with enriched column configs
         - Return generated rows
