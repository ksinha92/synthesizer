**Migration 026:**
```python
def upgrade():
    # Archive any non-null schedules first
    op.execute("""
        INSERT INTO _archived_workflow_schedules (workflow_id, schedule, archived_at)
        SELECT id, schedule, NOW() FROM workflows WHERE schedule IS NOT NULL
        ON CONFLICT DO NOTHING
    """)
    op.drop_column("workflows", "schedule")

def downgrade():
    op.add_column("workflows", sa.Column("schedule", sa.String(), nullable=True))
    # restore from archive
    op.execute("""UPDATE workflows w SET schedule = a.schedule
                 FROM _archived_workflow_schedules a WHERE a.workflow_id = w.id""")
```
Create the archive table in the same migration if it doesn't exist.

## F13 — Redis pub/sub for SSE progress

**Files:**
- **NEW** `backend/app/infrastructure/messaging/progress_pubsub.py` — `publish_progress(job_id: str, payload: dict)` helper. Uses sync Redis client (workers are sync). Channel: `f"job:{job_id}:progress"`. Payload includes status, progress, timestamp, optional result_summary.
- `backend/app/infrastructure/messaging/{discovery,masking,synthetic,subsetting,compliance,workflow}_tasks.py` — after each `JobModel` status/progress update, call `publish_progress(...)`. Wrap in try/except so Redis failure doesn't crash the worker.
- `backend/app/api/v1/events.py` — modify `_progress_stream`:
  1. Try `redis_client.subscribe(f"job:{job_id}:progress")`. On message yield SSE event.
  2. On Redis error (connection refused, etc.) fall back to the existing 2s DB poll loop.
  3. Add a 30s timeout on the Redis subscribe — if no message in 30s, send a heartbeat ping (mimics current behavior).
