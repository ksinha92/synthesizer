<objective>
## Goal
Build the Statistical synthetic engine (GaussianCopula + CTGAN) from scratch using copulas/ctgan libraries directly, plus quality evaluation with composite scoring — the core differentiator vs. Delphix.

## Purpose
Statistical synthesis preserves real data distributions and correlations. This is what makes DataWrangler's synthetic data usable for testing — not just random values (Faker) but statistically faithful reproductions. Quality evaluation proves it works.

## Output
- StatisticalEngine: GaussianCopula + CTGAN modes, multi-table support
- QualityEvaluator: composite score (0-100), per-column distribution comparison, privacy metrics
- Updated synthetic API with engine selection and quality endpoint
- Quality report frontend component
</objective>

    1. Add dependencies to pyproject.toml:
       - copulas>=0.12.0 (GaussianCopula synthesis)
       - ctgan>=0.11.0 (CTGAN deep learning synthesis)
       - scipy>=1.14.0 (KS tests, statistical comparisons)
       - cloudpickle>=3.0.0 (model serialization)
       - NOTE: Do NOT use sdmetrics — it's BUSL-licensed (DataCebo/SDV ecosystem). Implement quality metrics directly with scipy.stats (KS test, chi-squared) and numpy (correlation, distance). <!-- audit-added: license safety -->

    2. Create backend/app/infrastructure/engine/statistical_engine.py:
       - StatisticalEngine(BaseSyntheticEngine):
         - __init__(method: str = "gaussian_copula", config: dict = {})
         - Methods: "gaussian_copula" or "ctgan"

       - GaussianCopula mode:
         - _fit_copula(data: pd.DataFrame) -> GaussianMultivariate:
           - Use copulas.multivariate.GaussianMultivariate
           - Fit on source DataFrame
           - Handle mixed types: numeric columns directly, categorical via ordinal encoding
         - _sample_copula(model, num_rows) -> pd.DataFrame
           - Sample from fitted model
           - Decode categoricals back to original values

       - CTGAN mode:
         - _fit_ctgan(data: pd.DataFrame, epochs: int = 300, batch_size: int = 500) -> CTGANSynthesizer:
           - Use ctgan.CTGANSynthesizer
           - CRITICAL: run training in run_in_executor (dedicated ThreadPoolExecutor) — CTGAN is CPU-bound PyTorch, will block event loop if run in async context <!-- audit-added -->
           - Fit with configurable epochs and batch_size
           - Training timeout: 5 min default (enforced in executor wrapper)
           - Row sampling: if data > 50K rows, sample 50K for training (performance guard)
         - _sample_ctgan(model, num_rows) -> pd.DataFrame

       - Model persistence: <!-- audit-added -->
         - After fitting, serialize model to storage backend via cloudpickle
         - save_model(config_id, model) → stores at storage/{config_id}/model.pkl
         - load_model(config_id) → returns fitted model if exists
         - Subsequent generate() calls with same config skip fitting and load cached model
         - "Retrain" flag in config forces re-fitting

       - generate() implementation:
         - Load source data from connector (via connection + schema metadata)
         - For each table in config:
           - Fetch source data via connector.get_sample_data(limit=50000)
           - Fit model (copula or ctgan based on method)
           - Generate num_rows synthetic data
           - Apply column constraints (nullable %, unique for PKs)
         - For multi-table: generate in topological order (reuse Faker's _build_generation_order), assign FK values from parent tables
         - Return {table_name: [row_dicts]}

       - preview() implementation:
         - Same as generate but with limit=10 and reduced training (epochs=50 for CTGAN)

    3. Update domain/synthetic/value_objects.py:
       - Add EngineType.GAUSSIAN_COPULA and EngineType.CTGAN (already exist from Phase 6)
       - Verify GenerationMethod.STATISTICAL exists

    Avoid: Training CTGAN on > 50K rows without sampling — memory and time explosion.
    Avoid: Blocking the event loop during training — CTGAN training is CPU-bound, run in executor.
  </action>

<task type="auto">
  <name>Task 2: Implement QualityEvaluator with composite scoring and privacy metrics</name>
  <files>
    backend/app/infrastructure/engine/quality_evaluator.py,
    backend/app/api/v1/synthetic.py
  </files>
  <action>
    1. Create backend/app/infrastructure/engine/quality_evaluator.py:
       - QualityEvaluator class:
         - evaluate(real_data: pd.DataFrame, synthetic_data: pd.DataFrame) -> QualityReport

       - QualityReport dataclass:
         - composite_score: float (0-100)
         - column_scores: dict[str, {shape_score, type}]
         - column_pair_scores: dict[str, float]  (correlation preservation)
         - privacy_metrics: {dcr_mean, dcr_min, identical_matches, identical_match_pct}

       - Column shape scores:
         - Numeric columns: 1 - KS statistic (scipy.stats.ks_2samp)
         - Categorical columns: 1 - chi-squared divergence (normalize to 0-1)
         - Score per column: 0.0 (no match) to 1.0 (perfect match)

       - Column pair correlations:
         - Compute correlation matrix for real data (numeric cols)
         - Compute correlation matrix for synthetic data
         - Difference: mean absolute difference between matrices
         - Score: 1.0 - mean_abs_diff

       - Privacy metrics:
         - DCR (Distance to Closest Record): for each synthetic row, find nearest real row (Euclidean on numeric, exact match count on categorical). Report mean and min distance.
         - Identical matches: count synthetic rows that exactly match a real row. Should be 0 for good synthetic data.

       - Composite score:
         - Weighted average: 40% column shapes + 30% column pairs + 30% privacy
         - Scale to 0-100

    2. Update backend/app/api/v1/synthetic.py:
       - Add GET /api/v1/projects/{pid}/synthetic/configs/{id}/quality
       - Runs QualityEvaluator on stored synthetic vs source data
       - Returns full QualityReport as JSON
       - Cache result (quality score won't change for same data)

    CRITICAL: DCR computation is O(n*m). Hard cap: max 1K synthetic samples vs 5K real samples for DCR. Log warning if capping. <!-- audit-added -->

    Avoid: Running quality evaluation on full datasets — always sample for DCR.
  </action>
  <verify>
    - QualityEvaluator produces scores between 0-100
    - Column shape scores use KS test for numeric, chi-squared for categorical
    - Privacy metrics detect identical matches
    - Quality API endpoint returns JSON report
  </verify>
