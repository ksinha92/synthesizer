<objective>
## Goal
Encrypt connection credentials at rest with Fernet, implement key rotation, add S3-compatible storage backend, and upgrade JWT to RS256 — resolving the longest-standing deferred security issues.

## Purpose
Connection credentials have been plaintext JSONB since Phase 1 (deferred 21 phases ago). This is the #1 security debt item. Fernet encryption + key rotation + S3 storage completes the security posture for enterprise deployment.

## Output
- Fernet encryption/decryption service for credential fields
- Key rotation admin API
- S3-compatible storage backend (MinIO/AWS)
- JWT RS256 signing (asymmetric keys)
</objective>

<context>
## Deferred since Phase 1
- Connection credentials stored as plaintext JSONB — TODO comment in models/connection.py
</context>

<acceptance_criteria>

## AC-1: Credentials encrypted at rest with Fernet
```gherkin
Given a connection with username/password
When the connection is saved
Then the credentials JSONB contains Fernet-encrypted ciphertext, not plaintext
And when loaded, credentials are decrypted transparently for connector use
And the encryption key comes from FERNET_KEY environment variable
```

## AC-2: Key rotation re-encrypts all credentials
```gherkin
Given existing connections with Fernet-encrypted credentials
When POST /admin/rotate-encryption-key is called with a new key
Then all connection credentials are decrypted with old key and re-encrypted with new key
And the operation is atomic (all or nothing)
And an audit log entry records the rotation
```

## AC-3: S3-compatible storage backend works
```gherkin
Given STORAGE_BACKEND=s3 with S3 endpoint/bucket/credentials configured
When StorageBackend.save/load/delete are called
Then files are stored in the configured S3 bucket via boto3
And presigned URLs are generated for downloads
```
