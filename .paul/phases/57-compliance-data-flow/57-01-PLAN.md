# Phase 57 Plan 01 — Compliance + Privacy Hub Data-Flow

## Outcome

After this plan ships:
1. HIPAA/GDPR/CCPA PDFs contain real PII findings, masking rules, and connection listings sourced from `DiscoveryRepository` + `MaskingRepository` + `ConnectionRepository`.
2. `POST /api/v1/projects/{id}/compliance/reports` returns `202 Accepted` with a `job_id`; generation runs as a Celery task on the standard JobModel plane.
3. `POST /api/v1/projects/{id}/privacy-hub/apply-all` enqueues `run_masking_task` against the default policy and returns the job_id; the existing rule-creation logic runs first (idempotent).
4. Pre-v0.9 compliance reports get a `legacy=True` flag via migration 022 and surface that flag in the list/download responses.

## Implementation order

### F1 — Compliance handler reads real data
1. Resolve repo dependencies in `api/v1/compliance.py:47` — instantiate `SQLAlchemyDiscoveryRepository(session)`, `SQLAlchemyMaskingRepository(session)`, `SQLAlchemyConnectionRepository(session)`.
2. Rewrite `GenerateReportHandler.handle` body lines 40-43:
   - Connections: `await connection_repo.find_by_project_id(project_id)` → list of `{id, name, connector_type}`.
   - PII columns: for each connection, `await discovery_repo.find_by_connection_id(c.id)` → for each schema, `await discovery_repo.get_pii_columns(schema.id)` → flatten to `[{schema, table, column, pii_type, confidence}]`.
   - Masking rules: `await masking_repo.find_by_project_id(project_id)` → for each policy, `await masking_repo.get_rules_by_policy(p.id)` → flatten to `[{policy_name, column_id, strategy, enabled}]`.
3. Update reporter call: `reporter.generate(pii_columns, masking_rules, project_info)` (same signature).
4. Refresh narrative in `hipaa_reporter.py:33` from "pending Phase 18" → "RBAC enforced via authlib + project-scoped membership (see admin endpoints)".

### F2 — Move generation to Celery
1. Create `compliance_tasks.py`:
   - `@celery_app.task(bind=True, max_retries=2, autoretry_for=(Exception,), retry_backoff=True, acks_late=True)`
   - Updates JobModel status (`pending → running → completed/failed`), progress, result_summary (`{report_id, storage_path}`).
   - Sets `celery_task_id = self.request.id` (lays groundwork for F9 — won't fully ship until Phase 59 enum extension).
2. Update `api/v1/compliance.py POST /reports`:
   - Validate request, create `JobModel(project_id, job_type="compliance", status="pending", created_by=user_id)`.
   - Flush to get job.id, then `run_report_generation.delay(job_id=..., project_id=..., regulation=..., user_id=...)`.
   - Return `Response(status_code=202, content={"job_id": str(job.id), "status": "pending"}, headers={"Location": f"/api/v1/projects/{project_id}/jobs/{job.id}"})`.
3. Existing `list_reports` + `download_report` unchanged.

### F3 — Privacy Hub apply-all enqueues masking
1. In `api/v1/privacy_hub.py:apply_all_recommendations` after the rule-insert loop completes (`session.flush()`):
   - Resolve default policy via existing `_get_or_create_default_policy(project_id, session)`.
   - Find any connection for the project: `await SQLAlchemyConnectionRepository(session).find_by_project_id(project_id)` → take first.
   - Create JobModel + `run_masking_task.delay(policy_id=policy.id, connection_id=connection.id, job_id=job.id)`.
2. Update response schema to include `job_id: str | None`.
3. If no connection exists yet, skip the enqueue + return `job_id=null` + `note: "no_connection_to_mask"`.

### Migration 022 — legacy flag
1. `alembic revision --rev-id 022 --message "legacy_compliance_reports"` (handcraft file under `backend/alembic/versions/`).
2. Upgrade: `op.add_column("compliance_reports", sa.Column("legacy", sa.Boolean(), nullable=False, server_default=sa.text("false")))`, then `op.execute("UPDATE compliance_reports SET legacy = true")`.
3. Downgrade: `op.drop_column("compliance_reports", "legacy")`.
4. Update `ComplianceReportModel` + `ComplianceReport` entity + `ReportResponse` Pydantic.
