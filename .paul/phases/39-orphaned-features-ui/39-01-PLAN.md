<objective>
Wire 4 orphaned backend features into the frontend: schema introspection before discovery, webhook management, encryption key rotation, and dead letter queue visibility. Adds UI for backend endpoints that exist but have no consumer.
</objective>

<acceptance_criteria>
## AC-1: Schema Introspection Before Discovery
Given a connection with status "connected", when the user clicks "Run Discovery", then a schema selector modal appears showing live schemas fetched from GET /connections/{connection_id}/schemas. The user selects which schemas to discover, then confirms to trigger the discovery job. If the user selects all or skips selection, discovery runs as before (all schemas).

Frontend changes:
- Add `fetchSchemas(projectId, connectionId)` to connection-store.ts
- Create `SchemaSelector` component (modal with checkboxes)
- Wire into discovery page before `runDiscovery` call
- Pass selected schemas to runDiscovery (store in local state for display; backend discovers all regardless — schema filtering is a UI-side filter on results)

## AC-2: Webhook Management UI
Given the admin page, when user clicks the "Webhooks" tab, then they see a webhook management panel with:
- List of registered webhooks (url, events, active status, created date)
- "Add Webhook" form (url input, event multi-select: job.completed / job.failed)
- Delete button per webhook with confirmation
- Secret displayed once after creation in a copy-to-clipboard banner

Wired to existing endpoints:
- GET /projects/{project_id}/webhooks
- POST /projects/{project_id}/webhooks
- DELETE /projects/{project_id}/webhooks/{webhook_id}

Note: Webhook endpoints are project-scoped but admin-only. The admin page needs a project selector dropdown for webhook context.

## AC-3: Encryption Key Rotation UI
Given the admin page, add a "Security" section (new tab or within existing Audit tab) with:
- "Rotate Encryption Key" button
- Confirmation dialog explaining the impact (re-encrypts all connection credentials)
- Input for the new Fernet key
- Success/failure feedback with count of rotated connections

Wired to: POST /admin/rotate-encryption-key

## AC-4: Dead Letter Queue Viewer
Given the admin page or the jobs page, add a "Dead Letter Queue" tab showing:
- List of failed jobs that landed in DLQ (original_job_id, job_type, error_message, retry_count, resolved status)
- Paginated table
- "Resolved" badge for resolved entries

Backend: Add GET /admin/dead-letter-jobs endpoint (new) to list DLQ entries.
Frontend: Create DLQ viewer component wired to the new endpoint.
</acceptance_criteria>
