<objective>
## Goal
Build the `datawrangler` CLI tool for CI/CD integration, webhook notifications for job events, and API key management — so DataWrangler can be automated in pipelines without the web UI.

## Purpose
CI/CD integration is requirement #10. Teams need `datawrangler discover --connection X` in Jenkins/GitHub Actions pipelines. Webhooks notify Slack/email when jobs complete or fail.

## Output
- `cli/datawrangler/cli.py` — CLI commands: discover, mask, generate, subset, workflow run, status
- Webhook dispatcher: job completion/failure → HTTP POST to configured URLs
- API key management improvements
</objective>

<context>
## Prior Work
- Phase 2: JWT service account tokens (API key auth exists)
- Phase 9: Job system (all async operations create jobs)
</context>

<acceptance_criteria>

## AC-1: CLI tool runs TDM operations via API
```gherkin
Given the `datawrangler` CLI is installed
When `datawrangler discover --project <id> --connection <id> --api-key <key>` is run
Then it calls POST /discovery/run via the API and polls job status until complete
And `datawrangler status --job <id>` shows job progress
And `datawrangler mask`, `datawrangler generate`, `datawrangler subset` work similarly
```

## AC-2: Webhooks fire on job completion/failure
```gherkin
Given a webhook URL is configured for a project
When a job completes or fails
Then an HTTP POST is sent to the webhook URL with job details (id, type, status, duration)
And webhook delivery is logged for debugging
And failed webhook deliveries retry 3 times with backoff
```

## AC-3: Webhook CRUD API works
```gherkin
Given an authenticated admin user
When POST /projects/{pid}/webhooks is called with {url, events: ["job.completed", "job.failed"]}
Then the webhook is registered
And GET /projects/{pid}/webhooks lists configured webhooks
```

    1. Create ORM: WebhookModel (project_id, url, events JSONB ["job.completed", "job.failed"], is_active, secret_hash — store HMAC hash of secret, NOT plaintext. Return plaintext secret ONLY in creation response, never again. Like GitHub webhook secrets.) <!-- audit-added -->
    2. Create migration 011: webhooks table

    3. Create infrastructure/webhooks/dispatcher.py:
       - WebhookDispatcher:
         - dispatch(project_id, event_type, payload) -> None:
           - Load active webhooks for project matching event_type
           - For each: POST to url with JSON payload + X-Webhook-Signature header (HMAC of payload with webhook secret)
           - 3 retries with 5s/15s/60s backoff on failure
           - Log delivery status (success/failure + status code)
         - Non-blocking: run in background task

    4. Create api/v1/webhooks.py:
       - POST /projects/{pid}/webhooks — register webhook (requires admin)
       - GET /projects/{pid}/webhooks — list webhooks
       - DELETE /projects/{pid}/webhooks/{id} — remove webhook
       - All require auth

    5. Update API router

    Avoid: Synchronous webhook delivery — always background/async.
  </action>
