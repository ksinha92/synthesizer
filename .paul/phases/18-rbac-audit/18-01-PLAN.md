<objective>
## Goal
Implement role-based access control (admin/editor/viewer per project) with middleware enforcement, and a complete audit trail logging every API action with user, action, resource, timestamp, and IP.

## Purpose
RBAC prevents unauthorized data access — editors can modify, viewers can only read. Audit trail is required by HIPAA/GDPR/CCPA for post-incident reconstruction and compliance evidence.

## Output
- RBAC middleware: role checking on all project-scoped endpoints
- Audit trail: every API action logged to audit_logs table
- Admin UI: audit log viewer + RBAC role management
</objective>

<context>
## Prior Work
- Phase 2: Auth (get_current_user, require_role dependency)
- Phase 17: Compliance reports (need RBAC protection)
</context>

<acceptance_criteria>

## AC-1: RBAC enforces admin/editor/viewer per project
```gherkin
Given project roles: admin (full access), editor (CRUD, no delete project), viewer (read-only)
When an editor tries to DELETE /projects/{id}
Then 403 Forbidden is returned
And when a viewer tries to POST /masking/execute
Then 403 Forbidden is returned
And admin can perform all operations
```

## AC-2: Audit trail logs every API action
```gherkin
Given any authenticated API request
When the request completes (success or failure)
Then an audit_log entry is created: user_id, project_id, action, resource_type, resource_id, details, ip_address, timestamp
And audit logs are queryable via GET /admin/audit-logs
```

## AC-3: Admin UI shows audit log viewer and role management
```gherkin
Given an admin user visits /admin
When the page loads
Then the audit log viewer shows filterable entries (user, action, date range)
And the RBAC manager shows project members with role dropdowns
```

</acceptance_criteria>
